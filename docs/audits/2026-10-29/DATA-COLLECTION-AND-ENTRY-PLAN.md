Use the workbook's FORM FIELD AUDIT for individual original labels/input names, exact source links, backend destinations, requiredness, NULL treatment, role requirements and acceptance tests. This document groups staff collection tasks; it does not create new business rules or authorize importing held observations.

Dates use ISO YYYY-MM-DD when observed. Scores are numeric in[0,25], with precision subject to the recorded decision. Centre/staff/event identifiers must refer to verified canonical records; original source labels remain in restricted provenance. Identity evidence belongs in private review, not public technical logs. Missing data remains NULL/unknown, and aggregate gaps must not expose children's names or household details.

| Original operation | Current capability / required next contract |
|---|---|

| Assessment batch / row corrections | Existing record_assessment, score revision checks; current form/read path cannot handle valid NULL-date result. Need period-preserving correction and explicit absent/unrecorded handling; no date fabrication. |
| Named activity / participation | Existing event/participation operations cover limited scalar facts. Approved category/delivery model absent; original modal currently crashes. Participation saves require current role, historical context and audit. |
| CAC session / holiday / delivery | Calendar scheduling is supported; original delivery-status controls are not equivalent. Keep schedule and observed delivery separate. |
| Visits / follow-up / guidance / challenges | No approved canonical destination/API matching the original controls. Agree source, minimal schema, privacy and access before implementing. |
| Morarji | Existing approved flags/school only. Adapter omits the read data; original extra fields have no approved destinations. No assumed outcomes. |
| Removal / clear / undo | Original hard-delete/localStorage snapshot restoration is not a safe server contract. Approve per-record void/retire/restore, dependencies, retention, authorization and audit before implementation. |
| Export / print | Derive allowed identifying/aggregate shape from actual capability, apply identical effective scope, neutralize spreadsheet formula prefixes and avoid unnecessary private values. |

For every supported write: validate server-side, enforce RLS and exact historical keys, preserve row_version optimistic concurrency, make success depend on a confirmed server response plus re-read, and verify an audit event. Distinguish validation/authorization/conflict/network errors. An uncertain network commit must not be blindly retried as a new registration; use an approved idempotency contract or reconcile the intended existing record first. Keep all browser-only mutators visibly blocked in live review until persistence is implemented. Do not weaken private schemas or RLS to make a control appear functional.
