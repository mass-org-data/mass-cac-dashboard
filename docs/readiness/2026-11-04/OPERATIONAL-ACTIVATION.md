## Final hosted operational validation procedure

These are **future execution procedures, not evidence of completed hosted writes**. Use the exact READY Preview above, real managed Supabase Auth, only an already verified operator and the intended centre/date scope. No synthetic accounts, fabricated events, fake JWT subjects or fictitious grants in production. Do not paste credentials or full response payloads into reports. Test denial, concurrency and invalid-input write cases in the already isolated environment; an HTTP write-denial probe can commit if the implementation is unexpectedly defective.

Before a real operation: check installed capability, verify the operator's actual role/centre/profile capability, load the current scoped row/version, and record a private operation reference. Confirm source truth, explicit event date or documented quarter, supported enrolment/shift and absence of an existing record for an insert. Unknown shifts and unverified historical assignments stay unresolved. Do not manufacture a production observation merely to obtain a passing test.
